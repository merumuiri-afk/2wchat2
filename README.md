# 2WChat

Версия 1.12 переводит захват окна/монитора и предпросмотр на Windows
Graphics Capture с D3D11. Пул хранит два кадра; читается свежий, устаревшие
пропускаются. Буферы BGRA повторно используются до изменения размера.
JPEG-бюджет уменьшается при медленной записи в канал отправителя и плавно
восстанавливается при быстрой записи. Это локальная обратная связь отправки,
а не полноценная оценка пропускной способности до каждого зрителя.
Формат передачи сохранён: JPEG 5/10 FPS, без H.264. Нужен Windows 10
2004 (19041) или новее. Старый WM_PRINT остаётся только вспомогательным
кодом теста, запасного переключения на рабочий стол при ошибке окна нет.

Windows-установщик: `2WChat-X.Y.Z-Setup.exe` в GitHub Releases. Установка
для текущего пользователя в `%LOCALAPPDATA%\Programs\2WChat`, ярлыки
на рабочем столе (по умолчанию включён) и в меню «Пуск», штатное удаление
через параметры Windows. Профиль и стикеры в `%LOCALAPPDATA%\2WChat`
сохраняются при удалении. Встроенное автообновление использует прежний ZIP
и заменяет EXE в доступной для записи папке установленной программы.
Сборка: `./Tools/Build-Installer.ps1` после обычной сборки. Компилятор Inno
Setup скачивается с проверкой SHA-256 и подписи в переносном режиме в `.tools`.
Добавление установщика к уже опубликованному выпуску:
`./Tools/Publish-Release.ps1 -InstallerOnly`.

Версия 1.11 сохраняет GIF-стикеры исходными байтами: до 512×512 и 8 МиБ,
300 кадров / 32 млн пикселей по кадрам. Анимация работает в просмотрщике
и чате; в коллекции запускается при наведении, чтобы не анимировать все
стикеры сразу. Удаление фона для GIF не поддерживается. Возможность
согласуется при подключении: старые GIF-клиенты получают GIF без маркера
стикера, включая заголовок скачивания. Для отправки нужен сервер 1.11.
Предложение названия перенесено с меню «Сервис» на клик по синей полосе
с названием комнаты.

Версия 1.10: личная коллекция статичных стикеров через кнопку «Стикеры»
возле ввода сообщения или меню «Сервис → Мои стикеры». Картинка уменьшается
до 320 пикселей по большей стороне и сохраняется в PNG с прозрачностью.
Необязательное удаление фона — flood fill от краёв по цвету верхнего левого
пикселя; сложные фоны и выделение объектов нейросетью не реализованы.
До 100 стикеров хранятся в `stickers` профиля, с дедупликацией по SHA-256.
Передача использует существующий TLS image transport и флаг `isSticker`;
сервер проверяет PNG, предел 512×512 и 1 МиБ. Получателю устанавливать
коллекцию не требуется. В чате скрываются подпись, рамка и имя файла.
Картинку из чата можно добавить в коллекцию контекстным меню. Старые версии
могут показывать стикеры как обычные изображения; для специального вида
нужны обновлённые сервер и получатель.

Версия 1.9: «Сервис → Мини-окно участников» скрывает главное окно, сохраняя
сессию и аудиодвижок. Отдельное перемещаемое окно поверх остальных отображает
аватарки, речь (зелёная рамка), молчание, mute/deafen; обновление раз в 200 мс.
Закрытие мини-окна возвращает основной чат. Карточка входящего сообщения
показывает аватарку, имя и текст без активации окна, живёт 5 секунд и заменяется
новым сообщением. Нажатие возвращает чат. Звук, непрочитанные, фильтры истории
и собственных сообщений сохранены. Одновременно существует только одна карточка;
обычный значок в трее остаётся доступен.

Версия 1.8 добавляет выбор отдельного окна в демонстрации, обновление списка
и явный предпросмотр. WM_PRINT/SendMessageTimeout запрашивает только выбранный
HWND с проверкой процесса и ограничением ожидания 500 мс. Кадры рабочего стола
не используются как запасной вариант. Закрытые, скрытые и свёрнутые окна
останавливают показ; текущий размер проверяется на каждом кадре. Для изменения
размера окна media-сеанс объявляет предел 1280×720. Мониторный захват сохранён.
Некоторые игры, защищённые и GPU-окна могут возвращать чёрные кадры: для них
нужен мониторный режим. Системный курсор и звук в оконном режиме не передаются.

В 1.7.1 двойной щелчок по участнику или аватарке сообщения открывает
увеличенный просмотр. Окно меняет размер; используется исходная аватарка
96×96 из текущего кэша комнаты, без дополнительного сетевого запроса.

Версия 1.7: «Сервис → Предложить название комнаты» отправляет предложение
в чат и запрашивает подтверждение у владельца. Только локальный владелец
вызывает Rename; название транслируется текущим клиентам и позднему входу.
GIF передаётся исходными байтами, PictureBox воспроизводит кадры и задержки
в чате и просмотрщике. Старым клиентам отправляется подпись вместо GIF.
Лимиты: 8 МиБ, 300 кадров, 32 млн пикселей суммарно, 8 GIF в ленте.

Версия 1.6 добавляет аватарки: выбор/удаление через «Сервис → Моя аватарка»,
центральная обрезка до 96×96 JPEG до 12 КиБ, сохранение в профиле, показ
в списке участников и рядом с автором сообщения. Передача идёт отдельными
ограниченными TLS-пакетами после welcome, поэтому 16 аватарок не увеличивают
его размер. Сервер привязывает аватарку к авторизованному отправителю,
проверяет размер/заголовки, ограничивает частоту и хранит только актуальную
картинку участника. Поздний вход получает текущие аватарки; выход освобождает
кэш. Старые клиенты согласуют возможности и продолжают использовать чат.

Выпуски: https://github.com/merumuiri-afk/2wchat2/releases

Версия 1.5 проверяет GitHub Releases без авторизации, при запуске не чаще
раза в сутки или вручную из меню «Сервис». Проверку можно отключить.
Нужны стабильный тег `vX.Y.Z` и архив `2WChat-X.Y.Z-win-x64.zip` с GitHub
asset digest `sha256:…`. Приложение не устанавливает старые/prerelease версии.
Загрузка ограничена 160 МиБ, принимает только HTTPS GitHub, проверяет размер,
SHA-256 и FileVersion EXE. ZIP распаковывает только точный `2WChat.exe`,
игнорируя остальные пути. Установка возможна вне комнаты, по явной кнопке.
Отдельная копия текущего EXE ждёт завершения родителя, повторно проверяет
архив и атомарно заменяет EXE с резервной копией `.previous`. При отказе
запуска откатывает замену. Профиль `%LOCALAPPDATA%\\2WChat` и пользовательские
файлы не заменяются. Архивы/диагностика установки остаются в `updates` профиля.
SHA-256 защищает целостность доставки; доверие к выпуску опирается на HTTPS
и доступ к этому GitHub-репозиторию, отдельной цифровой подписи EXE пока нет.

Для следующего выпуска измените `Version` в `src/TwoWChat/TwoWChat.csproj`,
обновите `RELEASE-NOTES.md`, отправьте коммит и тег `vX.Y.Z`. Workflow
`.github/workflows/release.yml` соберёт Windows ZIP, выполнит автоматические
проверки и опубликует GitHub Release. В CI без звукового устройства пропускаются
проверки оборудования и интерактивный UI smoke; локально запускайте
`./Tools/Build.ps1 -AudioChecks`. `SHA256SUMS.txt` создаётся при сборке.
Для ручной публикации после сборки: `./Tools/Publish-Release.ps1` (использует
существующий вход Git Credential Manager или `GH_TOKEN` из окружения).

Самостоятельный голосовой и текстовый чат для Windows x64 и LAN/VPN.
Готовая программа: `dist/2WChat/2WChat.exe`; архив для друзей:
`dist/2WChat-1.4.0-win-x64.zip`. Пользовательская инструкция: [README-RU.txt](README-RU.txt).

Один EXE содержит клиент и сервер комнаты. Владелец создаёт комнату, остальные
подключаются по IPv4/имени узла и порту. До 16 участников, пароль, общий чат,
mute/deafen, выбор аудиоустройств, громкость, локальный mute участника, PTT,
тест микрофона, шумовой затвор и экспорт переписки. Для работы чата внешние сервисы не нужны.
Версия 1.1 добавляет звук входящих сообщений из пользовательского MP3,
уведомления в трее, счётчик непрочитанных и сохраняемые переключатели.
Собственные сообщения и история не вызывают уведомления; deafen глушит звук.
Звук встроен в EXE как PCM WAV; он играет на выбранном выходе через NAudio.
Оригинал и WAV находятся в `src/TwoWChat/Assets/MessageNotification.*`.
Повторить декодирование без изменения звучания можно утилитой
`Tools/AudioAssetBuilder` (вход MP3, выход WAV), использующей Windows ACM.
Версия 1.2 добавляет отправку изображений: выбор файла, Ctrl+V, drag-and-drop,
предпросмотр с подписью, миниатюры, просмотр 100% и сохранение. PNG/JPEG/GIF/BMP
подготавливаются в статичный PNG/JPEG до 8 МБ / 4096×4096. Фотографии учитывают
EXIF orientation, прочие метаданные удаляются. Новый флаг `supportsImages`
сохраняет совместимость текстового/голосового протокола с 1.0/1.1.
Изображения грузятся через TLS по запросу клиента, частями по 12 КиБ. Чат,
состояния и heartbeat имеют приоритет перед частями картинки. Welcome содержит
только метаданные. SHA-256, контроль смещений, ограничение незавершённых загрузок,
FIFO-кэш 32 МиБ и проверки размеров ограничивают память и неполные передачи.
Текст и голос продолжают работать при отмене или повреждении картинки.
Окно чата хранит до 180 записей / 250 тыс. символов / 32 МиБ изображений,
освобождая старые миниатюры и растровые ресурсы. Сохранение изображений — вручную.
Версия 1.3 добавляет отдельную громкость уведомлений 0–150% и её проверку
в настройках. `notificationVolume` сохраняется отдельно от `outputVolume`.
При первом чтении старого профиля значение наследуется от прежнего outputVolume,
после чего меняется независимо. Deafen по-прежнему глушит весь звук.

Версия 1.4 добавляет демонстрацию выбранного монитора: явный запуск/остановка,
один ведущий, несколько зрителей, отдельное окно и F11. Graphics.CopyFromScreen
снимает монитор только после Start; опциональный синтетический источник полностью
заменяет захват в QA. Кадры JPEG до 1280×720, 5/10 FPS, адаптивное сжатие с
бюджетом 500000 байт/с. Системный звук не захватывается. Это передача рабочего
стола, а не аппаратный H.264/WebRTC поток для 30/60 FPS.
Медиа идёт через отдельные SslStream на том же TCP listener. Новые подключения
привязаны к участнику случайным 256-битным ScreenKey, переданным в TLS welcome;
сертификат закреплён тем же SHA-256. Room token без ScreenKey не даёт доступ.
У отправителя, каждого зрителя и декодера — ограниченная очередь свежего кадра.
Версии списка трансляций защищают быстрый stop/start от устаревших событий.
Disconnect закрывает медиа, остановка очищает кадр. Кодировка/декодирование
выполняются вне UI потока. Старые клиенты не получают новый тип control-сообщений.

## Сборка и проверка

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\Build.ps1 -AudioChecks
```

Скрипт получает локальный официальный SDK .NET 10.0.403, проверяет SHA-512,
собирает код, запускает проверки, публикует автономный сжатый EXE для win-x64,
проверяет уже опубликованный EXE и создаёт ZIP. Первой сборке нужен Интернет.
Обычному пользователю SDK и .NET не нужны. `-AudioChecks` включает краткую
проверку реальных устройств ввода/вывода; звук микрофона не записывается.

Результаты: `artifacts/checks/checks.json`, `artifacts/ui-published/ui-smoke.json`
и PNG окон в той же папке. Сетевые тесты используют loopback; тест между двумя
реальными ПК через конкретную VPN требует этих ПК и не заменяется loopback.
Скрипт настройки брандмауэра не запускается сборкой и не меняет систему при QA.

После публикации можно отдельно проверить EXE:

```powershell
.\dist\2WChat\2WChat.exe --ui-smoke "$PWD\artifacts\manual-smoke"
```

Это создаёт изолированный тестовый профиль, комнату только на loopback,
клиента с синтетическим голосом и снимки окон. Комната затем закрывается.
Для отдельного обычного профиля доступен `--data-dir "путь"`.

## Реализация

* .NET 10, WinForms: нативные элементы, минималистичный интерфейс, без Electron.
* NAudio.WinMM 2.4.0: WaveInEvent/WaveOutEvent, PCM 48 кГц/16 бит/моно,
  захват 20 мс, воспроизведение с тремя буферами и целевой задержкой 60 мс.
* Нативный libopus через небольшую P/Invoke-обёртку и SafeHandle. Бинарник
  поставляется пакетом Concentus.Native 1.5.2; managed-кодек Concentus не нужен.
  Сжатие 24/32/48 кбит/с VBR, VOIP, complexity=5, FEC, DTX.
* Два сокета с одинаковым номером порта: TLS/TCP для length-prefixed UTF-8 JSON;
  UDP для голоса. TCP NoDelay, ограниченные очереди; голосовые просроченные
  кадры отбрасываются вместо накопления задержки.
* На каждый голосовой поток свой декодер и reorder/jitter-буфер. Декодирование
  привязано к часам аудиовывода. FEC/PLC, ограничение очереди, обнуление после
  длинной паузы; смешивание в 32 битах с ограничением итоговой амплитуды.
* Голос: AES-GCM, случайный 256-битный ключ на сессию, раздельные пространства
  nonce для направлений, аутентифицированный заголовок, 64-пакетное окно replay.
  UDP endpoint обновляется только после успешной проверки пакета.
* TLS-сертификат владельца сохраняется; доверие привязано к SHA-256 и адресу.
  Первое доверие пользователь подтверждает после сверки. Владелец видит трафик.
* Ограничение размера сообщений/пакетов/истории/участников, handshake timeout,
  ограничение входящих соединений и частоты чата/голоса, удаление зависших
  соединений. ID отправителя назначает сервер. Пароль передаётся только в TLS.
* Лёгкий high-pass + шумовой затвор с гистерезисом и плавным отпусканием.
  Нейросетевого шумоподавления и AEC нет; рекомендуется гарнитура.

`src/TwoWChat.Core` — транспорт, комната, шифрование, Opus, jitter и DSP.
`src/TwoWChat` — WinForms, аудиоустройства и локальные настройки.
`tests/TwoWChat.Checks` — интеграционные, алгоритмические и аппаратные проверки,
включая отдельные процессы сервера и двух клиентов.

Полезные первоисточники: [NAudio](https://github.com/naudio/NAudio),
[libopus API](https://opus-codec.org/docs/opus_api-1.5/),
[Opus over IP](https://datatracker.ietf.org/doc/html/rfc7587),
[native redistributable](https://www.nuget.org/packages/Concentus.Native/1.5.2).
